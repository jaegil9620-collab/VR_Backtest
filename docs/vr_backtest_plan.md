## 2. 책 규칙 → 엔진 로직

### 2.1 상태 변수
`V`(목표 평가금), `Pool`(현금), `shares`(보유수), `E`(사이클 마지막 날 종가 × 보유수)

### 2.2 초기화
1. 시작일 직전 거래일 종가 `P0`로 초기 자금을 나눈다: `shares = floor(초기자금 × (1 − 초기Pool비율) / P0)`, 나머지는 Pool.
   (책처럼 "2주~2달 분할매수로 모으기"는 옵션으로만 두고, 기본은 하루에 매수)
2. `V1 = shares × P0` (평단과 무관)

### 2.3 사이클 루프 (기본 2주 = 10거래일)
```
for 각 사이클:
    min_band = V × (1 − band_low),  max_band = V × (1 + band_high)
    buy_budget = 사이클 시작 Pool × pool_limit
    매수 사다리 k=1..: price_k = round(min_band / (shares0 + k − 1), 2)   # 누적 매수액이 한도 규칙을 넘기 전까지
    매도 사다리 k=1..: price_k = round(max_band / (shares0 − k + 1), 2)   # 한도 없음, 보유수 0이 되기 전까지
    사이클 기간의 일봉을 하루씩 돌며 체결 판정 (2.4)
    사이클 종료: E = shares × 마지막 종가
    V 갱신 (2.5) → 적립금 Pool 가산 / 인출금 Pool 차감 → 다음 사이클
```
- 사다리는 **사이클 시작 시 한 번 만들고 고정**(책의 "2주치 예약매매").
- 큰 계좌용 옵션: `lot_size` n주씩 묶어 주문(책: "2칸마다 2개씩").

### 2.4 체결 판정 (일봉 근사)
- 매수 주문: 그날 `저가 ≤ 지정가`면 체결. 체결가는
  - `limit`(책 방식): 지정가 그대로
  - `realistic`(기본 추천): 시가가 이미 지정가 아래로 갭하락했으면 시가, 아니면 지정가
- 매도 주문도 대칭(`고가 ≥ 지정가`, 갭상승 시 시가).
- 같은 날 매수·매도가 모두 걸리는 경우(하루 ±30% 이상 변동, 드묾): 설정 `same_day_order = buy_first | sell_first | skip`, 발생 횟수는 리포트에 경고로 표시.

### 2.5 V 갱신
- 기본공식: `V_new = V + Pool/G ± 적립금(인출금)`
- 실력공식: `V_new = V + Pool/G + (E − V)/(2·√G) ± 적립금(인출금)`
- Pool은 **사이클 마지막 Pool**(적립/인출 반영 전)을 쓴다. 책 예시: V2 = 4,999.5 + 0.5/10 + 250.
- G는 상수 또는 스케줄(예: 매년 +1, 평가금 구간별)로 설정 가능 — 책이 "G를 천천히 올리라"고 권하므로.

### 2.6 Pool 사용한도 해석 (책 예시를 역산해 확인한 점)
책 표의 "Pool의 75% 근처까지 매수"는 **누적 매수액이 한도에 가장 가까워지는 개수**로 정해져 있다(한도를 살짝 넘기도 함).
- 2사이클: Pool 250.50 × 75% = 187.9 → 5개(199.23) 선택, 4개(160.09)보다 가까움
- 3사이클: 500.50 × 75% = 375.4 → 9개(370.93)
- 예시3→4사이클: 1,044.70 × 75% = 783.5 → 18개(790.80)

따라서 설정 `pool_limit_rule = nearest(책 재현, 기본) | floor(절대 초과 안 함)`. 단, 실제 Pool이 부족하면 어느 경우든 매수하지 않는다.

### 2.7 목돈 추가/인출 (PART6_04)
이벤트 파일(날짜, 금액)로 입력. 현재 TQQQ:Pool 비율대로 나눠 매수/매도 + Pool 가감 → `V = Pool_new ÷ (P/V)_old`.
(Pool=0이면 P/V가 0이라 공식이 깨짐 → 이 경우 V를 평가금 비율로 늘리는 대체 규칙을 두고 경고)

### 2.8 책에 없는 경우 (결정 필요, 기본값 제안)
| 상황 | 제안 기본값 |
|---|---|
| 인출금 > Pool | 부족분만큼 다음 날 시가 매도 후 인출 (옵션: 인출 건너뛰기) |
| 휴장으로 2주 경계가 애매 | `cycle_mode = trading_days(10)` 기본, `calendar(월~다음주 금)` 선택 |
| 반올림 | 가격·금액 소수 둘째 자리(책 기준), 계산 중간값은 그대로 |
| 보유수 0 도달 | 매도 사다리 중단, 다음 사이클 매수만 |

## 3. 바꿀 수 있는 설정 (예: `config.yaml`)

```yaml
data:
  ticker: TQQQ            # 아무 종목 (SOXL, QLD, UPRO, QQQ ...)
  source: yfinance        # yfinance | csv | kis(한투 Open API, 2차)
  cache_dir: data/        # 받은 데이터는 CSV로 저장해 두고 재사용
  csv_path: null
  start: 2011-01-01
  end: 2020-12-31
  synthetic:              # 상장 전 기간 테스트용(닷컴버블 등)
    enabled: false
    base_ticker: QQQ      # 또는 ^NDX
    leverage: 3
    expense_ratio: 0.0095 # 연
strategy:
  mode: accumulate        # accumulate(적립) | hold(거치) | withdraw(인출)
  # 아래 값을 비워두면(null) 3.1의 책 기본값이 mode에 맞춰 자동 적용된다.
  # 값을 적으면 그 값이 책 기본값보다 우선한다.
  formula: basic          # basic | skill(실력공식)
  G: null                 # 숫자 또는 schedule
  band_low: null          # 예: 0.10 → 최소밴드 = V × 0.90
  band_high: null         # 위/아래 따로 지정 가능(비대칭 밴드)
  pool_limit: null        # 사이클당 Pool 사용한도
  pool_limit_rule: nearest
  cycle_mode: trading_days
  cycle_length: 10
  lot_size: 1
capital:
  initial: 5000
  initial_pool_ratio: null  # 시작 시 현금 비율
  periodic:
    type: fixed           # fixed(사이클당 고정 $) | ratio(비율)
    amount: null          # fixed일 때 $ (적립 +, 인출 −)
    ratio: null           # ratio일 때 비율, 예: 0.005 = 0.5%
    ratio_base: initial   # initial(최초 투자금) | total(현재 계좌총액)
  events_csv: null        # 목돈 추가/인출
costs:
  broker: kis             # 증권사 프리셋(kis=한국투자증권). 아래 값을 적으면 프리셋보다 우선
  commission_rate: 0.0025 # 거래대금 비율 (한투 기본 0.25%로 가정, 이벤트·우대율은 직접 수정)
  commission_min: 0.0     # 건당 최소 수수료($)
  commission_per_share: 0.0
  sec_fee_rate: 0.0000278 # 매도 시만
  slippage_bps: 0         # 체결가 불리하게 조정
  fx_spread: 0.0          # 원화 기준 결과 볼 때 환전 비용
  cash_yield: 0.0         # Pool 이자(연, 예: MMF·SGOV 가정)
  tax:
    enabled: false
    rate: 0.22            # 해외주식 양도세
    deduction_krw: 2500000
fill:
  price_model: realistic  # limit | realistic
  same_day_order: sell_first
report:
  out_dir: results/
  benchmarks: [TQQQ, QQQ, QLD]  # 단순 보유 비교
```

### 3.1 모드별 책 기본값 (프리셋)
`mode`만 고르면 아래 값이 들어가고, `config.yaml`에 직접 적은 값이 있으면 그 값이 우선한다. 실행 결과 맨 위에 "책 기본값 / 사용자 변경값"을 구분해 출력한다.

| 항목 | 적립식 | 거치식 | 인출식 | 책 근거 · 권장 범위 |
|---|---|---|---|---|
| G | 10 | 10 | 20 | PART4_01, PART6_03 (5~100 백테스트) |
| 밴드 (±) | 15% | 15% | 15% | PART4_01 (±10~20% 권장) |
| Pool 사용한도 | 75% | 50% | 25% | PART4_01 (10% 미만 비추천) |
| 초기 Pool 비율 | 0% | 10% | 20% | PART4_02 (0~10 / 10~20 / 20~30%) |
| 사이클당 적립·인출 | +250 $ (예시) | 0 | 최초 투자금의 0.5% | PART4_03, PART4_05 |

- 권장 범위를 벗어난 값을 넣어도 돌아가게 하되, 경고만 띄운다(예: 사용한도 5%, 밴드 ±30%).
- 적립·인출은 고정 금액과 비율 둘 다 지원한다. 인출식 기본은 책대로 "최초 투자금의 0.5%를 고정 금액으로" 계산한다.

## 4. 프로그램 구조 (Python)

```
vr_backtest/
  config.yaml
  vr/
    data.py        # 가격 로딩(yfinance/CSV), 분할 반영, 합성 레버리지
    calendar.py    # 사이클 구간 나누기
    ladder.py      # 매수·매도 사다리 생성 (책 표와 1:1)
    costs.py       # 수수료·슬리피지·세금 모델
    engine.py      # 사이클 루프, 체결 판정, V 갱신, 이벤트
    metrics.py     # CAGR, MDD, 변동성, 샤프, 매매 횟수, 수수료 총액
    report.py      # CSV + HTML 그래프
  cli.py           # python cli.py run config.yaml / sweep ...
  tests/           # 책 예시 재현 테스트
```
- 의존성: `pandas`, `numpy`, `yfinance`, `pyyaml`, `plotly`(그래프), `pytest`.
- `ladder.py`·`engine.py`는 순수 계산만 하도록 분리 → 나중에 자동매매에서 "이번 사이클 주문표 만들기"로 그대로 사용.

## 5. 결과물
1. **사이클 정리표 CSV**: 책 표와 같은 열(시작/마지막 평가금, V, 최소·최대밴드, 시작/마지막 Pool) + 체결 수, 수수료.
2. **체결 내역 CSV**: 날짜, 매수/매도, 수량, 가격, 수수료.
3. **요약 지표**: 최종 자산, CAGR, MDD, 총 투입·인출액, 매매 횟수, 수수료·세금 합계, 벤치마크 대비.
4. **그래프(HTML)**: 책 그림처럼 평가금·V·밴드·Pool 한 화면 + 계좌 총액/낙폭 곡선.
5. **파라미터 비교(sweep)**: G, 밴드폭, 사용한도, 수수료를 여러 값으로 돌린 표.
